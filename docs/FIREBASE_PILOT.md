# 웅비 Firebase 파일럿

## 이미 구현된 흐름
- Google 팝업 로그인 + 팝업 차단 시 redirect fallback
- 첫 로그인은 pending 계정 생성
- 담당교사가 학생/편집장 권한 승인
- 학생은 assigneeIds에 자기 UID가 들어간 기사만 조회
- 편집장은 전체 원고 검토 가능
- 담당교사만 기사 배정·승인·공개·책 확정
- 같은 기사 저장은 revision + Firestore transaction으로 충돌 감지
- 서로 다른 기사는 각 문서로 분리되어 여러 학생이 동시에 저장 가능
- 기사 변경은 onSnapshot으로 다른 기기의 변경을 감지

## 파일럿에서 확인할 것
1. 서로 다른 학생 10명이 각자 다른 기사 동시 저장
2. 공동기사 두 학생이 동시에 수정했을 때 덮어쓰기 대신 충돌 안내
3. 승인되지 않은 계정이 다른 학생 원고를 읽지 못함
4. 편집장이 학생 계정 권한을 바꾸지 못함
5. 담당교사만 승인·공개 가능
6. 로그아웃 후 공용 PC에서 이전 원고가 보이지 않음
7. 사진 원본은 private 경로, 공개본은 public 경로로 분리
8. 임시사진이 남아 있으면 승인/책 확정 차단

## 별도 Firebase 프로젝트
프로젝트 ID는 반드시 woonbi- 로 시작하고 indie 문자열을 포함하지 않도록 코드에서 검사합니다. INDI+P 프로젝트와 혼용하지 않습니다.

현재 이 브랜치에는 실제 Firebase 키나 학생 개인정보를 넣지 않습니다. 웹 설정은 별도의 live config로 주입하고 GitHub Secret 또는 로컬 비공개 파일에서 관리합니다.
