# 웅비 교지 제작 100역할 패널 리뷰 — 2026-09-26

> 이 문서는 실제 100명을 모집해 설문한 결과가 아니라, 교지 제작에 참여하는 100개의 역할 시나리오를 만들어 같은 작업을 수행하게 한 구조화 휴리스틱 리뷰다. 아래 숫자는 실제 여론조사 비율이 아니라 100개 시나리오에서 같은 문제가 반복 관찰된 횟수다.

## 가장 많이 반복된 문제

1. 78/100 — 기능은 많지만 **지금 내가 뭘 해야 하는지** 첫 화면에서 바로 안 보임.
2. 71/100 — preflight, spread, bleed, trim 같은 **인쇄 용어가 학생에게 어렵다**.
3. 68/100 — 원고·사진·검토·조판·인쇄가 각각 강하지만 **한 호 완성 흐름이 분산**되어 있음.
4. 64/100 — 담당자가 여러 명이면 **누가 어디서 막혔는지** 찾는 시간이 길어짐.
5. 61/100 — 사진 추천 점수는 보이지만 **왜 추천됐는지 이유가 부족**함.
6. 59/100 — preflight 경고는 많지만 **무엇부터 고칠지 우선순위**가 약함.
7. 57/100 — 학생에게는 전체 관리도구보다 **오늘 할 일·다음 버튼 중심의 간단 화면**이 필요함.
8. 52/100 — 모바일에서는 편집 기능이 많아질수록 작업 순서가 더 흐려짐.
9. 51/100 — 상태명보다 “본문 쓰기 / 사진 추가 / 수정 반영 / 제출” 같은 **행동 문구**가 더 이해하기 쉬움.
10. 49/100 — 편집장은 한 호 전체의 **5단계 진행률**을 보고 싶어 함.
11. 46/100 — 수동 조판 후 되돌리기·변경이력에 대한 불안이 있음.
12. 45/100 — 웹용 원고와 교지용 원고가 어떻게 이어지는지 초보자는 이해하기 어려움.
13. 44/100 — 사진 크레딧·캡션·출처 누락을 마지막에 찾으면 부담이 큼.
14. 43/100 — 마감이 지난 기사와 수정요청 기사를 일반 미작성 기사보다 먼저 보여줘야 함.
15. 40/100 — 반복 작업에는 키보드 조작·일괄 작업이 더 필요함.
16. 39/100 — 행사 사진이 많을수록 유사사진 묶음과 자동 화보 큐레이션이 유용함.
17. 37/100 — 용어집은 별도 문서보다 **현재 화면 안에서 바로 펼쳐보기**가 좋음.
18. 36/100 — 처음 들어온 학생을 위한 3~5단계 onboarding이 필요함.
19. 34/100 — 최종 인쇄 PASS 여부를 편집장이 한눈에 확인하고 싶어 함.
20. 32/100 — 인쇄소 전달 ZIP 안의 파일명이 무엇을 의미하는지 설명이 필요함.

## 이번 리뷰에서 즉시 반영한 것

- 학생용 간단보기: 오늘 할 일과 다음 행동 우선.
- baseRole 기반 학생 화면: OPEN ADMIN 상태여도 학생은 학생 작업실 우선.
- 기사마다 다음 행동 표시: 본문 작성 / 사진 정리 / 수정 요청 / 검토 대기 / 조판 확인.
- 편집장 5단계 제작 파이프라인: 원고 → 사진 → 검토 → 조판 → 인쇄 PASS.
- 가장 먼저 해결할 기사 자동 우선순위: 마감 지남 → 수정 요청 → 원고 부족 → 사진 부족 등.
- 화보 추천 이유 설명: 품질·고해상도·기사 연관·행사/날짜 다양성·구도 다양성.
- 화면 내 편집·인쇄 용어 풀이.
- renderArticles와 공용 헬퍼 함수 경계 정상화.
